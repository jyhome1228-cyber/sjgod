# 사자가온다 사이트 디자인 가이드 (2026-11-15)

## 색상 원칙 — 필수
- 사이트 UI는 **블랙(#000000) / 화이트(#FFFFFF)만** 기본으로 사용한다.
- 회색은 본문 위계와 구분선에만 사용하는 무채색 보조톤이다.
- 네이비, 청록, 연두, 주황 등 유채색은 배경, 버튼, 강조 텍스트, 아이콘에 사용하지 않는다.
- 모든 하위 페이지, 헤더, 푸터, 폼, 반응형 상태, hover 상태에 동일 적용한다.
- 사용자가 제공한 콘텐츠 사진/제품 이미지의 실제 색은 임의로 훼손하지 않는다. 이미지의 흑백화는 별도 요청 시 수행한다.

## 전체 방향
- 나인웍스·애플 사이트처럼 **내용 중심의 단정한 위계**를 적용한다.
- 'SAJAGAONDA / LECTURE', 'SPEAKER', 'PERFORMANCE ARCHIVE' 같은 장식용 영문 라벨을 사용하지 않는다.
- 슬래시, 대문자 영어 캡션, 강조 배경 박스, 불필요한 장식 기호와 과도한 카드 레이아웃을 쓰지 않는다.
- 사진이나 결과물처럼 실질적인 시각 자료를 중심에 둔다.
- 타이포그래피를 과장하지 않고, 빈 공간을 과도하게 확보하지 않는다.

## 크기와 간격
- 최대 콘텐츠 폭 1440px
- 메인 이미지 히어로 제목 30~42px
- 하위 페이지 H1 27~34px, 섹션 H2 23~30px, 카드/리스트 H3 17~19px
- 본문 13~15px, 안내/메타 12~13px
- 서브페이지 헤더는 짧은 타이틀+설명만 사용
- 섹션 상하 여백 PC 64px 내외, 모바일 43~48px
- 카드 대신 경계선과 리스트를 우선 활용. 카드가 필요하면 기능/콘텐츠에 근거하여 사용한다.
- 블랙 메인 브랜드 비주얼은 유지하되, 하위 페이지는 화이트 위주로 단정하게 구성한다.

## 품질 검사
- 메인, 프로그램, 솔루션, 교구·교재, 실적, 대표 강연, 회사소개, 도입 문의, 뉴스 전 페이지 공통 규칙 적용
- 모바일에서 제목의 과도한 줄바꿈, 헤더 메뉴, 콘텐츠 밀도 확인
- 실제 운영 내용 외 '제공된 자료', '전략안 기준', '디자인 참고', '향후 추가' 같은 내부 작업 안내 문구는 고객 노출 최소화
- 배포 성공 여부는 GitHub Actions / Pages에서 별도 확인한다.
